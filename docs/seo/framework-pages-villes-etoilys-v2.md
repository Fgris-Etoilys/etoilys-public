# Framework de création des pages villes Etoilys

**Version :** 2.0 — 23 juillet 2026  
**Projet :** site public Etoilys  
**Usage :** document autonome destiné à ChatGPT pour rechercher, concevoir et rédiger une page ville Etoilys, puis produire un prompt complet à transmettre à Codex pour son intégration dans le site.

---

## 1. Finalité du framework

Etoilys souhaite publier progressivement des pages locales répondant à des recherches telles que :

- `classement meublé de tourisme Bergerac` ;
- `organisme classement meublé Bordeaux` ;
- `faire classer un gîte à Périgueux` ;
- `tarif classement location saisonnière Agen`.

Chaque page doit être une **landing page locale de service**, et non un article de blog, une fiche administrative ou un guide juridique.

Elle doit permettre au propriétaire de comprendre rapidement :

- qu’Etoilys intervient dans son secteur ;
- ce que propose Etoilys ;
- pourquoi faire appel à Etoilys ;
- comment se déroule la démarche ;
- combien la prestation coûte ;
- sous quel délai la visite peut être organisée ;
- comment déposer une demande.

Le principe général est le suivant :

> Une structure commune, des composants communs et des arguments de marque cohérents, mais une copy locale réellement spécifique à chaque ville ou bassin.

La page doit être utile, agréable à lire, suffisamment différenciée pour le SEO et clairement orientée vers la demande de classement.

---

## 2. Ordre de priorité

Pour chaque décision éditoriale, utiliser l’ordre de priorité suivant :

1. **Répondre précisément à l’intention de recherche locale et maximiser le potentiel SEO de la page** ;
2. **Transformer le visiteur en demande de classement** ;
3. **Rassurer sur Etoilys, son expertise et la simplicité de la démarche** ;
4. **Apporter une différenciation locale réelle et utile** ;
5. **Garantir l’exactitude des informations et la maintenabilité de la page**.

Le SEO ne doit jamais être interprété comme une obligation d’allonger artificiellement le texte, de répéter le mot-clé ou d’ajouter des développements réglementaires sans intérêt commercial.

Une bonne page locale SEO :

- répond vite à la requête principale ;
- couvre les questions secondaires réellement recherchées ;
- utilise naturellement le nom de la ville, du bassin et du département ;
- contient une valeur locale propre ;
- présente une offre claire ;
- inspire confiance ;
- bénéficie d’un maillage interne cohérent ;
- ne ressemble pas à une page générée où seul le nom de la ville a été remplacé.

---

## 3. Principe fondamental : séparer la recherche interne de la copy publique

ChatGPT doit travailler en deux couches distinctes.

### 3.1 Dossier de recherche interne

La recherche peut être détaillée et prudente. Elle peut contenir :

- rattachements communaux et EPCI ;
- composition des territoires ;
- tarifs complets de taxe de séjour ;
- taxes additionnelles ;
- déclarations et enregistrements ;
- délibérations locales ;
- changement d’usage ;
- règles propres à une commune ;
- statistiques touristiques ;
- sources, dates et méthodes de calcul ;
- informations vérifiées mais finalement écartées de la page ;
- précautions nécessaires à l’exactitude du travail.

Cette matière sert à sécuriser la rédaction. Elle n’a pas vocation à être publiée intégralement.

### 3.2 Copy publique

La copy visible ne conserve que les informations qui :

- renforcent le SEO local ;
- aident à choisir Etoilys ;
- répondent à une objection commerciale ;
- montrent une connaissance réelle du secteur ;
- expliquent un bénéfice du classement de manière concrète ;
- facilitent la demande de classement.

Une information trouvée pendant la recherche **ne doit jamais être intégrée automatiquement** dans la page.

Par défaut, les développements suivants restent dans le dossier interne :

- longues explications sur les EPCI ;
- détails de procédure administrative locale ;
- état complet du droit applicable ;
- sanctions ;
- historique réglementaire ;
- liste exhaustive des communes d’une intercommunalité ;
- notes méthodologiques ;
- phrases défensives et disclaimers ;
- précisions qui n’aident pas directement le propriétaire à comprendre l’offre ou à agir.

### 3.3 Règle de simplification

Avant d’intégrer une phrase dans la copy, ChatGPT doit se demander :

> Cette phrase aide-t-elle réellement le propriétaire à trouver la page, à comprendre l’offre, à faire confiance à Etoilys ou à déposer une demande ?

Si la réponse est non, la phrase reste dans le dossier de recherche.

La rigueur doit être dans les coulisses. Elle ne doit pas rendre la page pénible à lire.

---

## 4. Positionnement éditorial et ton

La page doit donner l’impression qu’Etoilys est :

- un véritable expert du classement des meublés de tourisme ;
- un organisme sérieux et accrédité ;
- un interlocuteur accessible ;
- une entreprise qui simplifie la démarche ;
- une solution rapide, claire et bien organisée ;
- un acteur équipé d’outils utiles pour préparer et suivre le classement.

### 4.1 Ton attendu

- professionnel mais naturel ;
- direct ;
- rassurant ;
- dynamique sans être agressif ;
- orienté propriétaire ;
- phrases plutôt courtes ;
- paragraphes aérés ;
- bénéfices concrets ;
- vocabulaire compréhensible sans connaissance du classement.

Le texte peut s’adresser directement au propriétaire avec `vous`.

### 4.2 À éviter

- ton administratif ;
- jargon non expliqué ;
- phrases défensives ;
- précautions répétées ;
- inventaire de règles ;
- paragraphes longs ;
- démonstration juridique ;
- style universitaire ;
- emphase commerciale vide ;
- promesses non vérifiables ;
- répétition du même argument dans plusieurs blocs.

### 4.3 Formulations typiquement indésirables dans la copy publique

Sauf nécessité exceptionnelle, ne pas écrire :

- `Au [date précise], les modalités restent à préciser…` ;
- `Selon le statut du logement et la commune…` ;
- `Dans le cas présenté…` ;
- `Aucune procédure spécifique n’a été identifiée…` ;
- `Les règles peuvent évoluer indépendamment du classement…` ;
- `Les communes relevant de l’EPCI…` ;
- `Le classement ne dispense pas des formalités applicables…` ;
- `Le montant réel dépend du prix, du nombre de voyageurs, des exonérations et de la situation du logement…` ;
- `Il convient de vérifier auprès de l’autorité compétente…`.

Ces précisions peuvent être nécessaires pour la recherche interne. Elles ne doivent apparaître sur la page que si leur absence rendrait l’affirmation trompeuse.

### 4.4 Longueur indicative

Il n’existe aucun quota strict.

La plupart des pages devraient probablement se situer autour de **900 à 1 500 mots, FAQ comprise**, mais une page peut être plus courte ou plus longue selon la ville et la richesse réelle du contenu.

Les longueurs servent uniquement de garde-fous :

- aucun bloc ne doit être gonflé pour atteindre un nombre de mots ;
- aucune information réellement utile ne doit être supprimée pour respecter un plafond arbitraire ;
- chaque paragraphe doit contribuer au SEO, à la confiance, à la compréhension ou à la conversion.

---

## 5. Conditions préalables à la création d’une page

Avant de recommander la publication, ChatGPT doit confirmer les éléments suivants.

### 5.1 Éléments obligatoires

- ville ou bassin ciblé ;
- département parent ;
- slug envisagé ;
- intervention réelle d’Etoilys dans le secteur ;
- principales communes habituellement couvertes ;
- modalités tarifaires Etoilys ;
- délai d’intervention applicable ;
- image locale exploitable légalement ou brief d’image précis ;
- au moins un angle local réellement utile ;
- sources suffisantes pour vérifier les informations publiées ;
- possibilité de différencier la page de la page départementale ;
- date de vérification des données locales.

### 5.2 Éléments facultatifs

- partenariat avec un office de tourisme ;
- tarif partenaire ;
- inspecteur du secteur ;
- témoignage local ;
- nombre d’interventions réalisées ;
- cas client ;
- photo d’une intervention réelle ;
- spécificité d’organisation des tournées.

L’absence de ces éléments ne bloque pas la page. Les modules correspondants doivent simplement être omis.

### 5.3 Raisons de ne pas publier

Ne pas recommander la page si :

- Etoilys n’intervient pas réellement dans le secteur ;
- la zone n’est couverte qu’exceptionnellement sans conditions claires ;
- la page ne pourrait apporter aucune valeur propre par rapport à la page départementale ;
- la copy ne serait qu’un remplacement automatique du nom de la ville ;
- les tarifs ou modalités essentiels sont inconnus ;
- les informations locales importantes sont invérifiables.

---

## 6. Architecture éditoriale commune

Ordre recommandé :

1. **Hero local** ;
2. **Zone d’intervention** ;
3. **Particularités locales et exemple concret de taxe de séjour** ;
4. **Déroulement du classement** ;
5. **Tarifs et modalités** ;
6. **Pourquoi choisir Etoilys ?** ;
7. **Preuve ou ancrage local — facultatif** ;
8. **FAQ locale et commerciale** ;
9. **CTA final**.

Le fil d’Ariane, les métadonnées SEO, le maillage et les sources internes de vérification ne sont pas des blocs éditoriaux visibles.

L’ordre peut être légèrement adapté si l’architecture réelle du site ou l’intention de recherche le justifie, mais le hero, les informations commerciales et le CTA doivent rester facilement accessibles.

# Bloc 1 — Hero local

## Statut

Obligatoire.

## Objectif

En quelques secondes, le visiteur doit comprendre :

- que la page concerne sa ville ou son bassin ;
- qu’Etoilys réalise le classement officiel des meublés de tourisme ;
- que la visite se déroule sur place ;
- qu’il peut demander un classement immédiatement.

## Contenu attendu

- sur-titre local facultatif ;
- H1 ;
- chapô court ;
- CTA principal vers `/demande-classement` ;
- CTA secondaire vers `/simulateur` ou `/procedure` ;
- image locale ;
- texte alternatif pertinent.

## Modèle de H1

```text
Classement de meublé de tourisme à [VILLE] et dans [BASSIN]
```

Le H1 peut être adapté si une autre formulation correspond mieux à la requête principale.

## Principes de rédaction

- répondre immédiatement à l’intention locale ;
- utiliser naturellement la requête principale ;
- rester court ;
- donner envie d’agir ;
- ne pas expliquer le fonctionnement complet du classement ;
- ne pas prétendre qu’Etoilys possède une agence locale si ce n’est pas le cas ;
- ne pas accumuler artificiellement `gîte`, `Airbnb`, `location saisonnière`, `étoiles` et tous les noms de communes.

## Image locale

L’image doit :

- représenter réellement la ville ou le bassin ;
- être exploitable légalement ;
- être suffisamment qualitative pour un hero ;
- être intégrée au pipeline d’images existant ;
- ne pas laisser croire qu’un logement photographié est un client Etoilys si ce n’est pas le cas.

Le livrable doit fournir :

- sujet de l’image ;
- lieu représenté ;
- source ;
- auteur ;
- licence ;
- obligations de crédit ;
- alt recommandé ;
- alternative si aucune image exploitable n’est trouvée.

Codex ne doit jamais intégrer une image dont le droit d’utilisation n’est pas établi.

# Bloc 2 — Zone d’intervention

## Statut

Obligatoire.

## Objectif

Permettre au propriétaire de vérifier rapidement qu’Etoilys intervient près de son logement.

## Contenu attendu

- ville principale ;
- bassin ou agglomération ;
- sélection lisible de communes habituellement desservies ;
- mention non exhaustive ;
- invitation à transmettre l’adresse si la commune n’est pas citée ;
- éventuelles conditions particulières pour les zones plus éloignées.

## Principe de rédaction

Le bloc doit rester commercial et facile à parcourir.

Ne pas afficher :

- la liste administrative complète de l’EPCI ;
- les codes Insee ;
- les explications de rattachement institutionnel ;
- les communes qui ne sont pas réellement couvertes ;
- les distinctions territoriales qui ne servent pas la compréhension de l’offre.

## Formulation de portée

L’idée suivante doit être présente, sans nécessairement reprendre les mots exacts :

> La liste n’est pas exhaustive. Si votre commune n’apparaît pas, envoyez-nous simplement l’adresse du logement pour vérifier les prochaines possibilités d’intervention.

## Règle géographique interne

La zone commerciale Etoilys peut couvrir plusieurs EPCI.

En revanche, une information locale sur la taxe de séjour ou une règle communale ne doit être appliquée qu’au territoire réellement concerné.

Cette vérification doit être faite dans le dossier de recherche. Elle ne doit pas conduire à publier de longues explications administratives sur la page.

---

# Bloc 3 — Particularités locales et exemple concret

## Statut

Obligatoire dans son principe, modulaire dans son contenu.

## Rôle SEO et commercial

Ce bloc constitue le principal différenciateur local de la page.

Il doit :

- donner une couleur locale réelle ;
- enrichir la pertinence sémantique de la page ;
- montrer qu’Etoilys connaît le territoire ;
- expliquer un bénéfice concret du classement ;
- rester court, vivant et orienté propriétaire.

Il ne doit pas devenir un guide de la réglementation locale.

## 3.1 Introduction locale

Le bloc peut commencer par une à trois phrases présentant agréablement la ville ou le bassin et reliant immédiatement cette présentation au tourisme ou aux locations saisonnières.

Exemple de style :

> Au cœur du Périgord pourpre, Bergerac est connue pour ses vignobles, son lien avec Cyrano et son attractivité touristique. Gîtes, maisons de vacances et locations saisonnières y occupent naturellement une place importante.

La formulation doit être adaptée à la ville et vérifiée.

À éviter :

- inventaire de monuments ;
- paragraphe de brochure touristique ;
- adjectifs génériques comme `destination incontournable`, `cadre idyllique` ou `joyau touristique` ;
- histoire locale sans rapport avec la location ou le classement ;
- statistiques de population sans utilité.

## 3.2 Sélection des informations locales

Retenir seulement un ou deux éléments utiles parmi les suivants :

- effet local du classement sur la taxe de séjour ;
- particularité touristique directement reliée aux hébergements ;
- typologie de biens réellement rencontrée par Etoilys ;
- possibilité de regrouper plusieurs visites ;
- organisation des interventions dans le bassin ;
- partenariat local confirmé ;
- ressource locale réellement utile ;
- règle locale particulièrement importante, seulement si elle répond à une forte intention de recherche.

Ne pas intégrer par défaut :

- déclaration en mairie ;
- enregistrement ;
- changement d’usage ;
- limitation de nuitées ;
- sanctions ;
- détail de délibérations ;
- droit national déjà expliqué ailleurs sur le site.

Ces sujets n’apparaissent que s’ils sont réellement spécifiques au territoire, fréquemment recherchés et utiles à la conversion ou à la compréhension immédiate.

## 3.3 Exemple systématique de taxe de séjour

Lorsque les tarifs locaux permettent une comparaison fiable, intégrer un exemple simple et visuel.

### Scénario de référence

Utiliser, sauf raison particulière :

- **150 € la nuit** ;
- **4 adultes** ;
- comparaison entre **meublé non classé** et **meublé classé 2 étoiles** ;
- résultat principal pour **une nuit** ;
- projection secondaire pour **sept nuits**.

L’utilisation du même scénario facilite la cohérence entre les pages.

### Calcul interne

ChatGPT doit :

1. identifier le taux applicable au non-classé ;
2. identifier le tarif local total applicable à un meublé 2 étoiles ;
3. intégrer correctement les taxes additionnelles ;
4. vérifier les plafonds éventuels ;
5. calculer le montant par nuit pour quatre adultes ;
6. calculer la différence en euros ;
7. calculer la réduction en pourcentage ;
8. multiplier les montants par sept pour la projection hebdomadaire ;
9. vérifier les calculs avant de fournir la copy.

### Présentation visible recommandée

```text
Exemple à [VILLE]
150 € la nuit · 4 adultes

Non classé : [X €] par nuit
Classé 2 étoiles : [Y €] par nuit

[DIFFÉRENCE €] de moins par nuit · soit environ –[Z %]
Sur 7 nuits : [ÉCONOMIE HEBDOMADAIRE €]
```

Afficher à la fois :

- les montants précis ;
- la différence en euros ;
- le pourcentage ;
- la projection sur sept nuits.

Ne pas afficher uniquement un pourcentage abstrait.

Ne pas utiliser 120 nuits comme projection standard : cela suppose un niveau d’occupation, un prix et une composition de séjours constants.

### Mention courte

Une mention très discrète peut suffire :

```text
Tarifs [ANNÉE] de [TERRITOIRE].
```

Ne pas ajouter de long disclaimer expliquant que le montant dépend du nombre de voyageurs, des exonérations ou de la situation du logement.

### Cas où le module doit être omis ou adapté

- données locales insuffisantes ;
- comparaison impossible ;
- scénario donnant un résultat trompeur ;
- tarif 2 étoiles non disponible ;
- plafonds ou taxes additionnelles impossibles à vérifier ;
- absence d’avantage dans le scénario retenu.

Ne jamais modifier artificiellement les hypothèses pour produire un pourcentage spectaculaire.

## 3.4 Sources de recherche recommandées

### Géographie

- Insee — Code officiel géographique ;
- base officielle des EPCI ;
- sites officiels des communes et intercommunalités.

### Taxe de séjour

- portail officiel de la collectivité ;
- délibération locale ;
- données DELTA ;
- portail DGFiP ;
- office ou organisme officiellement chargé de la collecte.

### Tourisme

- office de tourisme ;
- agence départementale ou régionale ;
- observatoire touristique ;
- Insee ;
- DGE ;
- données publiques identifiables.

### Règles locales exceptionnelles

- Légifrance ;
- Service-Public ;
- ville ;
- EPCI ;
- préfecture ;
- délibération officielle.

Les sources servent à la recherche et à la maintenance. Elles ne doivent pas être transformées automatiquement en section visible sur la landing page.

# Bloc 4 — Déroulement du classement

## Statut

Obligatoire et largement mutualisable.

## Objectif

Faire comprendre que la démarche est simple.

La page ville n’a pas vocation à reproduire la page `/procedure`.

## Structure recommandée

Trois étapes courtes :

### 1. Vous envoyez votre demande

Quelques informations sur le logement permettent de commencer et de confirmer les modalités d’intervention.

### 2. Nous organisons la visite

Etoilys confirme le tarif et propose une date dans le secteur.

### 3. Nous réalisons le classement

La visite est effectuée sur place, puis le propriétaire reçoit les documents officiels correspondant au classement obtenu.

## Principes

- rester simple ;
- éviter les détails réglementaires ;
- ne pas lister le rapport, la grille, la proposition de décision et chaque délai ;
- ne pas expliquer CLASS ou le rôle des organismes institutionnels ;
- ajouter un lien vers `/procedure` pour le détail.

---

# Bloc 5 — Tarifs et modalités

## Statut

Obligatoire.

## Objectif

Répondre rapidement à la question du prix et expliquer les principales variations.

## Contenu attendu

- prix ou fourchette confirmée ;
- éventuel tarif standard ;
- tarif préférentiel pour les adhérents d’un office partenaire, uniquement si le partenariat est confirmé ;
- intervention urgente plus coûteuse ;
- tarifs dégressifs pour plusieurs logements situés dans le même secteur ;
- éventuels frais de déplacement ;
- CTA vers la demande de classement.

## Règle tarifaire stricte

Les tarifs Etoilys sont des informations métier à confirmer pour chaque page. Le framework ne doit jamais fixer de prix par défaut, même sous forme d’exemple réutilisable.

Avant de produire une copy finale ou un prompt Codex intégrable, ChatGPT doit vérifier que les montants, la qualification TTC/HT, les partenariats OT, la dégressivité, les frais de déplacement et les conditions particulières sont explicitement fournis dans le contexte ou confirmés par Florian.

Si ces informations ne sont pas disponibles, le livrable doit poser une série de questions consolidées et laisser le bloc tarif en attente. Il ne faut pas inventer de prix, reprendre un montant d’une autre ville, ni transformer une ancienne page en référence tarifaire générale.

## Principes

- annoncer clairement les montants validés ;
- ne pas inventer de prix ;
- ne pas reproduire une grille tarifaire complexe ;
- ne pas noyer le prix sous des réserves ;
- préciser simplement que le montant est confirmé avant engagement ;
- ne pas laisser penser que le tarif le plus élevé s’applique systématiquement.

## Questions métier à poser si nécessaire

- les prix sont-ils TTC, HT ou affichés sans qualification ?
- quel est le prix standard ?
- quel est le tarif partenaire ?
- à quelles conditions s’applique-t-il ?
- comment est défini le tarif urgent ?
- quelles conditions déclenchent la dégressivité ?
- plusieurs logements doivent-ils appartenir au même propriétaire ?
- faut-il les visiter le même jour ?
- des frais de déplacement existent-ils dans le secteur ?

ChatGPT doit regrouper les questions manquantes en une seule demande concise.

# Bloc 6 — Pourquoi choisir Etoilys ?

## Statut

Obligatoire.

## Objectif

Rendre les avantages d’Etoilys explicites sans citer ni dénigrer les concurrents.

Le bloc doit être visuel, court et facilement parcourable, par exemple sous forme de quatre ou cinq cartes.

## Arguments à intégrer

### 6.1 De vrais experts du classement

Idée à exprimer :

> Le classement des meublés de tourisme est la spécialité d’Etoilys. L’équipe maîtrise précisément le référentiel et aide le propriétaire à comprendre les critères de la catégorie visée.

Éviter les formulations vagues comme `une expertise inégalée`.

### 6.2 Un organisme accrédité Cofrac

Mention de référence :

> Etoilys est un organisme accrédité Cofrac Inspection n°3-2394 pour réaliser les visites officielles de classement des meublés de tourisme.

Conserver la formulation de marque ou la mention Cofrac validée dans le repo lorsqu’elle diffère.

### 6.3 Une démarche simple, sans dossier lourd

Idée à exprimer :

> Quelques informations sur le logement suffisent pour lancer la demande. Etoilys organise la visite sans imposer au propriétaire de constituer un dossier administratif complexe.

Ne pas prétendre qu’aucun document ne sera jamais demandé si ce n’est pas vrai.

### 6.4 Une intervention rapide

Les délais mentionnés concernent **la date de la visite après réception de la demande**.

Copy recommandée :

> Nous intervenons généralement sous deux semaines, et toujours dans un délai maximal d’un mois après votre demande.

Cette distinction entre délai d’intervention et délai de remise des documents doit être comprise par ChatGPT et Codex. Elle n’a pas besoin d’être expliquée au lecteur dans la page.

Si le délai varie selon la zone, la saison ou l’urgence, poser la question à Florian avant de rédiger.

### 6.5 Des outils qui facilitent l’obtention de la catégorie visée

Etoilys peut affirmer que ses outils facilitent l’obtention du classement souhaité, car ils permettent d’identifier précisément les critères restant à valider et les justificatifs complémentaires recevables.

Copy possible :

> Nos simulateurs et outils de suivi vous indiquent précisément les critères à compléter pour atteindre la catégorie visée. Vous préparez plus efficacement votre logement et savez quels justificatifs transmettre lorsqu’un complément est possible.

Ou :

> Vous savez exactement ce qu’il vous manque pour viser la catégorie souhaitée. Nos outils vous permettent d’ajuster les derniers critères et de transmettre les justificatifs nécessaires lorsqu’ils peuvent être pris en compte.

Règles :

- ne pas garantir l’obtention d’une catégorie ;
- ne pas laisser entendre que le référentiel est appliqué avec davantage de souplesse ;
- expliquer que l’avantage vient de la précision des outils et du suivi ;
- ne pas citer les concurrents ;
- ne pas attribuer de mauvaises pratiques à `la concurrence` ou `aux autres organismes`.

## Comparaison implicite autorisée

La page peut inviter le lecteur à comparer des critères objectifs sans attribuer de chiffres aux concurrents.

Exemple :

> Avant de choisir votre organisme, comparez le coût total, le délai d’intervention, les outils de préparation et les services compris dans la prestation.

Ne pas publier un tableau `Etoilys / La concurrence` avec des délais, prix ou performances non démontrés.

# Bloc 7 — Preuve ou ancrage local

## Statut

Facultatif.

## Objectif

Renforcer la crédibilité locale avec une preuve réelle.

## Éléments possibles

- avis d’un client du secteur ;
- photo d’une intervention réelle ;
- nombre de visites réalisées ;
- partenariat confirmé ;
- inspecteur affecté au secteur ;
- cas concret anonymisé ;
- retour d’expérience local.

## Règle d’affichage

Si aucune preuve réelle n’est disponible :

- supprimer totalement le bloc ;
- ne pas afficher de titre vide ;
- ne pas réserver d’espace ;
- ne pas transformer un avis national en preuve locale ;
- ne rien inventer.

---

# Bloc 8 — FAQ locale et commerciale

## Statut

Recommandé, mais son volume dépend des questions réellement utiles.

## Objectif

Couvrir des recherches secondaires, lever des objections et compléter la page sans recopier ses sections.

## Volume indicatif

En général : **trois à six questions**.

Il n’existe aucun minimum strict.

Une FAQ courte et utile vaut mieux qu’une FAQ longue et répétitive.

## Critères de sélection d’une question

Une question doit remplir au moins une condition :

- correspondre à une recherche secondaire intéressante ;
- lever une objection non traitée ailleurs ;
- préciser un cas particulier ;
- apporter une information complémentaire ;
- aider le visiteur à déposer sa demande.

## Questions possibles

- Etoilys intervient-il dans les communes autour de `[VILLE]` ?
- Sous quel délai une visite peut-elle être organisée ?
- Faut-il préparer beaucoup de documents avant la visite ?
- Peut-on regrouper plusieurs gîtes le même jour ?
- Comment savoir quelle catégorie viser ?
- Que se passe-t-il s’il manque quelques critères après la visite ?
- Existe-t-il un tarif préférentiel dans le secteur ?
- Etoilys intervient-il pour un logement situé hors de la liste affichée ?

## Gestion des répétitions

Une question SEO telle que :

> Combien coûte le classement d’un meublé à `[VILLE]` ?

peut être conservée même si un bloc tarif existe, mais sa réponse doit :

- rester courte ;
- synthétiser ;
- ajouter une précision utile ;
- ne pas recopier mot pour mot le bloc tarif.

Ne pas créer automatiquement des questions sur :

- la déclaration en mairie ;
- le numéro d’enregistrement ;
- la limite de location de la résidence principale ;
- la durée de validité du classement ;
- le détail de la procédure nationale ;
- les sanctions.

Ces questions ne sont intégrées que si elles correspondent à une intention locale ou commerciale réellement utile.

## Style des réponses

- directes ;
- courtes ;
- non répétitives ;
- sans longues précautions ;
- orientées vers l’action lorsque cela est naturel.

Ne pas promettre de résultat enrichi FAQ dans Google.

# Bloc 9 — CTA final

## Statut

Obligatoire.

## Objectif

Transformer la lecture en action.

## Contenu attendu

- titre local ;
- phrase courte ;
- rappel de l’étape suivante ;
- CTA principal vers `/demande-classement` ;
- CTA secondaire facultatif vers `/contact` ou `/simulateur`.

## Exemple de structure

```text
Vous souhaitez faire classer votre meublé à [VILLE] ?

Envoyez-nous l’adresse du logement et quelques informations. Nous vous confirmons rapidement le tarif et les prochaines disponibilités dans le secteur.

[Déposer ma demande de classement]
[Poser une question]
```

Éviter :

- pression commerciale ;
- fausse urgence ;
- répétition de tout le contenu de la page ;
- formulaire long intégré sans nécessité.

## 7. SEO local

## 7.1 Intention de recherche

ChatGPT doit identifier :

- requête principale ;
- variantes naturelles ;
- questions secondaires ;
- intention dominante ;
- concurrence interne avec les pages départementales ou nationales.

L’intention principale est généralement transactionnelle ou commerciale : trouver un organisme, connaître le tarif, vérifier la zone et demander une visite.

Les sujets réglementaires ne doivent pas prendre le dessus sur cette intention, sauf ville présentant une particularité locale majeure très recherchée.

## 7.2 Métadonnées

Le livrable doit fournir :

- slug ;
- H1 ;
- meta title ;
- meta description ;
- canonical ;
- département parent ;
- date de vérification locale.

Modèles indicatifs :

```text
Slug : /classement-meuble-tourisme-[ville]
H1 : Classement de meublé de tourisme à [VILLE] et dans [BASSIN]
Title : Classement meublé de tourisme à [VILLE] | Etoilys
Description : Faites classer votre meublé de tourisme à [VILLE] et dans les communes proches. Visite sur place, tarifs clairs et demande en ligne.
```

Adapter les formulations à la recherche réelle et à la longueur des titres.

## 7.3 Différenciation avec la page départementale

La page départementale :

- présente une couverture large ;
- sert de page parente ;
- décrit l’intervention à l’échelle du département.

La page ville :

- répond à l’intention de proximité ;
- présente les communes proches ;
- expose les tarifs et délais applicables ;
- contient un bloc local spécifique ;
- apporte un exemple concret ;
- conduit directement vers la demande.

ChatGPT doit expliciter cette différenciation dans le livrable.

## 7.4 Maillage interne

Ajouter des liens naturels vers les routes pertinentes, en fonction de l’architecture réelle :

- page départementale parente ;
- `/zones-intervention` ;
- `/procedure` ;
- `/les-avantages-du-classement` ;
- `/simulateur` ;
- `/simulateur-taxe-sejour` ;
- `/faq` ;
- `/demande-classement` ;
- `/contact`.

Ne pas surcharger la page de liens.

Ne rien ajouter :

- sur la page d’accueil ;
- dans la navigation principale ;
- dans le footer.

Les pages villes sont principalement accessibles depuis :

- `/zones-intervention` ;
- la page départementale parente ;
- éventuellement d’autres pages locales lorsque le lien est pertinent.

## 7.5 Données structurées

- conserver l’architecture JSON-LD existante ;
- ajouter les breadcrumbs selon les conventions du repo ;
- ne pas créer un faux `LocalBusiness` propre à la ville ;
- ne pas inventer d’adresse ou d’agence locale ;
- ne pas déclarer une implantation physique inexistante ;
- ne pas ajouter manuellement un schéma isolé si le SEO est centralisé.

## 7.6 Images

- image réellement locale ;
- alt descriptif ;
- dimensions adaptées ;
- pipeline d’images existant ;
- pas de hotlink ;
- crédits et licences respectés ;
- image hero cohérente avec la copy.

## 7.7 FAQ et SEO

La FAQ sert :

- la couverture de requêtes secondaires ;
- la compréhension ;
- la conversion.

Elle ne doit pas être allongée dans le seul but de créer davantage de texte.

## 8. Recherche locale à effectuer

ChatGPT doit rechercher suffisamment pour sécuriser la page, sans imposer que toutes les informations trouvées apparaissent dans la copy.

## 8.1 Géographie

Rechercher :

- commune cible ;
- bassin naturel ;
- département ;
- EPCI principal ;
- communes voisines ;
- EPCI secondaires éventuellement couverts ;
- zone commerciale réelle d’Etoilys.

Rechercher :

- attractivité touristique ;
- types d’hébergement ;
- saisonnalité si elle est utile ;
- données de l’office ou de l’observatoire ;
- formulation courte permettant de relier la ville aux meublés de tourisme.

Ne pas chercher à produire un portrait exhaustif de la destination.

## 8.3 Taxe de séjour

Rechercher :

- territoire collecteur ;
- année des tarifs ;
- taux du non-classé ;
- plafond ;
- tarifs par étoile ;
- taxes additionnelles ;
- exemptions utiles au calcul interne ;
- source officielle ;
- scénario de comparaison standard.

## 8.4 Modalités Etoilys

Confirmer :

- intervention réelle ;
- délai moyen ;
- délai maximal ;
- tarif standard ;
- urgence ;
- visites groupées ;
- partenariat OT ;
- frais de déplacement ;
- outils disponibles ;
- preuve locale éventuelle.

Les prix, les mentions TTC/HT, les tarifs partenaires, les conditions de dégressivité et les éventuels frais ne doivent pas être déduits du framework, du web ou d’une page précédente. Si ces informations ne figurent pas clairement dans le brief, ChatGPT doit les demander à Florian avant de figer la copy tarifaire.

Ces informations doivent provenir du contexte Etoilys ou de Florian, jamais d’une déduction du web.

## 8.5 Règles locales facultatives

Rechercher seulement si elles peuvent être utiles :

- enregistrement ;
- déclaration ;
- changement d’usage ;
- plafond local de location ;
- copropriété ;
- autres formalités.

Leur présence dans le dossier de recherche ne justifie pas leur publication.
